# Автоматическое развертывание и обучение моделей (Cron)
Bash-скрипт для автоматического отслеживания изменений в Git-репозитории, подтягивания обновлений для указанных веток и запуска скриптов обучения моделей в отдельных tmux-сессиях. Скрипт использует планировщик задач Cron для периодической проверки репозитория.

## 🚀 Фишки
- **Автоматическое обновление репозиториев:** Периодически проверяет указанные Git-ветки на наличие новых коммитов.

- **Поддержка нескольких веток/моделей:** Отслеживает любое количество веток, заданных в конфигурационном файле.

- **Изолированный запуск обучения:** Запускает скрипты обучения в отдельных tmux-сессиях, позволяя им работать в фоновом режиме, даже если терминал закрыт.

- **Гибкая конфигурация:** Все ключевые параметры (пути, URL репозитория, имена скриптов) хранятся в отдельном конфигурационном файле.

- **Логирование:** Подробные логи всех операций записываются в файл для удобства отладки и мониторинга.
___
## Особенности работы cron-версии
1. Настроить пути и доступы к файлам.
    1. Прописать пути в `watcher_cfg.sh`.
    2. Указать модели (ветки) для проверки в `branches_to_monitor.txt`.
2. Прописать задание и частоту в _cron_.

Скрипт проверяет раз в указанное время различия между локальной и удалённой версией каждой ветки, указанной в `branches_to_monitor.txt`. Если есть различия, изменения переносятся на машину и запускается указанный файл из скопированной ветки в tmux сессию.
Если директории под новую ветку нет локально на машине, скрипт создаст директорию и продолжит работу в штатном режиме.

## ⚙️ Установка и настройка

Клонируйте этот репозиторий в удобную директорию. Для удобства используйте отдельную папку:

```Bash
cd <dirname>/watcher
```
```Bash
git clone --branch cron --single-branch https://github.com/toochkinberg/watcher.git
```

В репозитории находятся следующие файлы:
    `watcher.sh` (основной скрипт)
    `watcher_cfg.sh` (файл конфигурации)
    `branches_to_monitor.txt` (файл со списком веток)

### Настройка файлов скрипта
__watcher_cfg.sh__ (файл конфигурации) содержит переменные, которые _НЕОБХОДИМО ПОМЕНЯТЬ_:

>`BASE_REPOS_DIR`=_"/home/your\_user/neural\_projects/models"_
>Путь к базовой директории, где будут храниться клонированные репозитории моделей.
>
>`GIT_REPO_URL`=_"git@github.com:user/repo.git"_
>URL Git репозитория.
>
>`BRANCHES_FILE`=_"\$(dirname "$(readlink -f "$0")")/branches\_to\_monitor.txt"_
>Полный путь к файлу со списком веток для мониторинга.
>По умолчанию текстовик в той же директории, что и этот скрипт.
>
>`TRAIN_SCRIPT`=_"test.py"_
>Имя скрипта обучения, который находится в корне каждой клонированной ветки.
>Этот скрипт будет запускаться в tmux-сессии при обнаружении изменений.
>
>`LOG_FILE`=_"\$(dirname "$(readlink -f "$0")")/watcher.log"_
>Полный путь к файлу логов скрипта развертывания.
>По умолчанию текстовик в той же директории, что и этот скрипт
>Все выводы скрипта будут перенаправлены сюда.

__branches_to_monitor.txt__ (файл со списком веток) содержит названия веток, которые проверяет скрипт.

>Каждая ветка должна быть на новой строке. Пустые строки и строки, начинающиеся с #, игнорируются.

_Пример содержимого:_
```
model_1
feature/new_model_v2
bugfix/hotfix_v1
```

### Предоставление прав на исполнение
Убедитесь, что основной скрипт __watcher.sh__ является исполняемым:

```Bash
chmod +x watcher.sh
```

### Cron
1. Запустить Cron
```Bash
sudo service cron start
```

2. Добавить задачу
```Bash
crontab -e
```
Добавить следующую строку в конец файла. Обратить внимание на полный путь к _watcher.sh_:

```
* * * * * /home/your_user/neural_projects/watcher/watcher.sh
```
3. Сохранить и выйти.

## Дополнительно
Проверить активные tmux-сессии:

```Bash
tmux ls
```
Если скрипты обучения были запущены, будут сессии с именами вроде __model_training_model_1_....__

Можно подключиться к сессии, чтобы увидеть вывод обучения: 
```bash
tmux attach -t <имя_сессии>
```
